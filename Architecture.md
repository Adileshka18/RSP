# Архитектура информационной системы SavorLink

## Общая информация

SavorLink — информационная система автоматизации взаимодействия между предприятиями общественного питания и поставщиками продуктов питания и сырья.

Система предназначена для упрощения процессов поиска поставщиков, управления каталогами продукции, оформления заказов, отслеживания поставок и обмена информацией между участниками закупочной деятельности.

Основными пользователями системы являются представители ресторанов и кафе (покупатели) и представители поставщиков продукции.

---

# Архитектурный стиль

Система реализована на основе клиент-серверной архитектуры.

Архитектура обеспечивает разделение пользовательского интерфейса, бизнес-логики и слоя хранения данных, что упрощает сопровождение, тестирование и дальнейшее масштабирование системы.

Взаимодействие между компонентами осуществляется посредством REST API.

# Контейнеры системы

## Web Client

Технологии:

- Vue.js
- Vite
- Vue Router
- Pinia

Назначение:

- отображение пользовательского интерфейса;
- авторизация пользователей;
- просмотр каталога поставщиков;
- управление корзиной;
- оформление заказов;
- работа с отзывами;
- обмен сообщениями.

---

## Backend Service

Технологии:

- Python
- FastAPI
- SQLAlchemy

Назначение:

- обработка запросов клиентов;
- управление бизнес-логикой системы;
- управление пользователями;
- управление предприятиями;
- управление товарами;
- обработка заказов;
- управление отзывами;
- работа с чатами;
- отправка уведомлений.

---

## Database

Технологии:

- PostgreSQL

Назначение:

- хранение данных пользователей;
- хранение данных предприятий;
- хранение информации о товарах;
- хранение заказов;
- хранение истории изменений;
- хранение отзывов;
- хранение сообщений.

---

## Notification Service

Технологии:

- WebSocket

Назначение:

- уведомления о новых заказах;
- уведомления об изменении статуса заказа;
- уведомления о новых сообщениях;
- уведомления о действиях пользователей.

---

# Диаграмма контейнеров C4

Система включает следующие контейнеры:

- Web Application (Vue.js + Vite);
- Backend API (FastAPI);
- PostgreSQL Database;
- Notification Service (WebSocket).

Взаимодействие пользователей с системой осуществляется через веб-интерфейс. Frontend взаимодействует с Backend посредством REST API. Backend обеспечивает обработку бизнес-логики и взаимодействует с базой данных PostgreSQL. Для доставки уведомлений используется сервис WebSocket.

# Пользовательские роли

## Покупатель

Покупатель представляет предприятие общественного питания.

Основные возможности:

- поиск поставщиков;
- просмотр товаров;
- управление корзиной;
- оформление заказов;
- отслеживание заказов;
- добавление поставщиков в избранное;
- оставление отзывов.

---

## Поставщик

Поставщик представляет производителя или поставщика продукции.

Основные возможности:

- управление каталогом товаров;
- обработка заказов;
- изменение статусов заказов;
- управление информацией о предприятии;
- взаимодействие с покупателями;
- получение отзывов.

# Логика работы системы

Работа системы начинается с регистрации и авторизации пользователя.

Покупатель получает доступ к каталогу поставщиков и товаров. После выбора необходимых товаров пользователь формирует корзину и создаёт заказ.

Заказ поступает поставщику для обработки. Поставщик может изменять статус заказа в зависимости от этапа выполнения.

После завершения поставки покупатель имеет возможность оставить отзыв о поставщике и приобретённой продукции.

Система также предоставляет возможность обмена сообщениями между пользователями посредством встроенного чата.

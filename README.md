# SavorLink

## Описание проекта

SavorLink представляет собой информационную систему автоматизации взаимодействия между предприятиями общественного питания и поставщиками сырья и продуктов питания. Система предназначена для оптимизации процессов поиска поставщиков, оформления заказов, управления каталогом товаров и контроля поставок.

Основными пользователями системы являются покупатели (представители ресторанов и кафе) и поставщики продукции.

---

# Пользовательские роли

## Покупатель

Покупатель осуществляет поиск поставщиков, просматривает каталог продукции, оформляет заказы и отслеживает их выполнение.

Основные функции:

* регистрация и авторизация;
* поиск поставщиков;
* просмотр товаров;
* формирование корзины;
* оформление заказа;
* отслеживание статуса заказа;
* подтверждение получения товара;
* оставление отзывов.

## Поставщик

Поставщик управляет каталогом продукции и обрабатывает поступающие заказы.

Основные функции:

* регистрация и авторизация;
* управление товарами;
* обработка заказов;
* изменение статусов заказов;
* подтверждение поставки;
* просмотр отзывов и рейтингов.

---

# Основные сущности системы

В информационной системе используются следующие ключевые сущности:

1. Пользователь (User);
2. Предприятие (Enterprise);
3. Товар (Product);
4. Заказ (Order);
5. Отзыв (Review).

---

# Архитектура системы

Архитектура приложения построена по клиент-серверному принципу.

Frontend реализован с использованием Vue.js и обеспечивает взаимодействие пользователей с системой через веб-интерфейс.

Backend реализован на FastAPI и содержит бизнес-логику приложения, обработку запросов пользователей и взаимодействие с базой данных.

Для хранения данных используется СУБД PostgreSQL.

Для отправки уведомлений пользователям используется сервис WebSocket-соединений.

---

# Диаграмма контейнеров C4

Система включает следующие контейнеры:

* Web Application (Vue.js + Vite);
* API Application (FastAPI);
* Database (PostgreSQL);
* Notification Service (WebSocket).

Взаимодействие осуществляется по протоколу HTTPS через REST API.

---

# База данных

Структура базы данных разработана в соответствии с требованиями третьей нормальной формы (3NF).

Основные сущности связаны отношениями:

* пользователь принадлежит предприятию;
* предприятие публикует товары;
* покупатель формирует заказы;
* заказ содержит товары;
* пользователи оставляют отзывы поставщикам.

ER-диаграмма базы данных приведена в отдельном разделе проекта.

# Заключение

Разработанная архитектура информационной системы SavorLink обеспечивает масштабируемость, удобство сопровождения и разделение ответственности между компонентами системы. Использование современной клиент-серверной архитектуры позволяет обеспечить эффективное взаимодействие между ресторанами и поставщиками продукции, а также автоматизировать основные бизнес-процессы закупочной деятельности.
